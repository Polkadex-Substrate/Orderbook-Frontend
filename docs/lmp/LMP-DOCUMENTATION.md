## 1. What is LMP?

**LMP (Liquidity Mining Program)** is Polkadex's on-chain market-making incentive system. It rewards traders who provide liquidity (place limit orders close to the mid-price) with PDEX tokens at the end of each epoch.

### Core Concepts

| Term | Meaning |
|---|---|
| **Epoch** | A fixed block-range scoring period (~7 days, 201,600 blocks at 12s/block). Rewards are distributed at epoch end. |
| **Q-Score** | A composite liquidity quality score: `Q = Depth × Uptime × MakerVolume`. Ranges 0–1. |
| **Tier** | Markets are grouped: Tier 1 (tightest spreads, most rewards), Tier 2, Tier 3. |
| **DMM** | Designated Market Maker — an account that commits to specific spread/depth/uptime and receives a guaranteed stipend. |
| **Merkle Proof** | Each claimable reward is backed by a Merkle proof generated by the backend. The on-chain `claim_rewards` extrinsic verifies it. |
| **Volatility Multiplier** | A 2× boost applied to Q-score contributions during high-volatility periods. |

### Reward Calculation

```
Epoch reward = (user Q-score / sum of all Q-scores) × epoch reward pool
```

Each pair in an epoch has its own reward pool. A user who traded across multiple pairs can claim separate rewards per pair.

              │             │  REST: /lmp/epochs         │
              └────────────►│  REST: /lmp/leaderboard    │

### Data Source Strategy

| Data | Source | Freshness |
|---|---|---|
| Epoch list + status | REST `GET /lmp/epochs` | On-mount + manual |
| Leaderboard | REST `GET /lmp/epochs/{n}/leaderboard` | Every 60s |
| DMM assignments | REST `GET /lmp/dmm` | Every 30s |
| Claimable rewards + proofs | REST `GET /lmp/accounts/{addr}/rewards/claimable` | On-mount, refetch after claim |
| User Q-score (live) | WebSocket `/lmp/accounts/{address}` | Real-time push (~60s intervals from backend) |
| Market snapshots (live) | WebSocket `/lmp/live` | Real-time push, last 60 buffered |

## 3. Full End-to-End Flow

### 3.1 User views the LMP dashboard

```
User navigates to /rewards/PDEX-WETH
       │
       ▼
middleware.ts checks ENABLE_LMP env var
       │ (allowed)
       ▼
rewards/[id]/page.tsx  →  rewardsPreview/template.tsx (ssr: false)
       │
       ├── useProfile()  →  gets mainAddress (Polkadot SS58)
       ├── useMarkets()  →  resolves market metadata for PDEX-WETH
       │
       ├── EpochOverviewPanel
       │     ├── useEpochs()  →  finds current ongoing epoch
       │     ├── useAccountQScore(mainAddress)  →  WebSocket: rank, est. reward, scores
       │     └── Renders: epoch #, time remaining, user rank, est. PDEX reward
       │
       ├── QScoreGauges
       │     └── useAccountQScore(mainAddress)  →  depth/uptime/volume arcs
       │
       ├── MarketTierSelector
       │     └── useLmpPairs()  →  REST: lists all pairs w/ tier, spread, DMM flag
       │
       ├── DMMPanel (collapsible)
       │     └── useDMMs()  →  REST: DMM assignments w/ live uptime bars
       │
       ├── Left panel — Tabs
       │     ├── "My Trading Rewards" tab
       │     │     └── TableRewards (existing)  →  AppSync/GraphQL
       │     └── "LMP History" tab
       │           └── useLMPHistory(mainAddress)  →  REST: claimable rewards + proofs
       │                 └── RewardRow → ClaimModal (on Claim button click)
       │
       └── Right panel
             └── LMPLeaderboard
                   └── useLMPLeaderboard(epoch, pair)  →  REST: top 20 entries
                         └── Self-row highlighted if user is in top 20
                         └── Sticky bottom row if user is outside top 20
```

### 3.2 User claims a reward

```
User clicks "Claim" on an unclaimed reward row (LMPHistoryTab)
       │
       ▼
ClaimModal opens
       │
       ├── Shows: epoch #, pair, amount (formatted PDEX), Merkle proof summary
       │
User clicks "Confirm Claim"
       │
       ▼
usePolkadotExtrinsic.submit()
       │
       ├── State → "signing"
       ├── Gets signer from Polkadot.js extension (getSigner)
       ├── Builds extrinsic:
       │     api.tx.ocex.claimRewards(
       │       reward.epoch,
       │       api.createType("u128", BigInt(reward.amount)),
       │       reward.merkleProof   // Vec<H256>
       │     )
       │
       ├── State → "submitted" (hash available)
       │
       ▼
Extrinsic finalized on chain
       │
       ├── State → "success" (hash)
       ├── Shows: "Reward claimed!" + link to polkadex.subscan.io/extrinsic/{hash}
       └── Invalidates query cache:
             queryClient.invalidateQueries(QUERY_KEYS.lmpHistory(address))
             queryClient.invalidateQueries(QUERY_KEYS.lmpRewards("", address))
```

### 3.3 WebSocket live score updates

```
useAccountQScore(address) mounted
       │
       ├── Connects to ws://{LMP_WS_URL}/lmp/accounts/{address}
       ├── On message: updates qScore state → QScoreGauges re-renders
       ├── On close: exponential backoff reconnect (1s → 2s → 4s → ... → 30s cap)
       └── On address change: closes old socket, opens new one

useLMPLive() mounted
       │
       ├── Connects to ws://{LMP_WS_URL}/lmp/live
       ├── On message: prepends snapshot to buffer (max 60)
       ├── latestSnapshot drives real-time leaderboard refresh
       └── On close: exponential backoff reconnect
```

## 7. Hooks

All hooks live in `packages/core/src/hooks/lmp/`.

### Data Hooks (REST via TanStack Query)

| Hook | Query Key | Refetch Interval | Description |
|---|---|---|---|
| `useEpochs()` | `epochs()` | On-mount | All epochs with status (Ended/Ongoing/Upcoming). Derives status from block height. |
| `useLmpPairs()` | `lmpPairs()` | On-mount | All LMP-enabled pairs with tier, max spread, min depth, DMM flag, volatility flag. |
| `useLMPLeaderboard(epoch, pair?)` | `lmpLeaderboardV2(epoch, pair)` | 60,000ms | Top N leaderboard entries. Disabled when `epoch === 0`. |
| `useDMMs()` | `lmpDMMs()` | 30,000ms | Active DMM assignments with live uptime. |
| `useLMPHistory(address)` | `lmpHistory(address)` | On-mount | Claimable + claimed rewards with Merkle proofs. Disabled when no address. |

### WebSocket Hooks

| Hook | Endpoint | Description |
|---|---|---|
| `useAccountQScore(address)` | `/lmp/accounts/{address}` | Live Q-score stream for the current user. Returns `{ qScore, connected }`. Reconnects with exponential backoff (1s → 30s cap). Resets qScore to null when address changes. |
| `useLMPLive()` | `/lmp/live` | Market-wide snapshot stream. Returns `{ snapshots[], connected, latestSnapshot }`. Buffers last 60 snapshots. Same backoff strategy. |

### Extrinsic Hook

`usePolkadotExtrinsic()` — Generic hook for any Polkadot extrinsic.

```typescript
const { state, submit, reset } = usePolkadotExtrinsic();

// state.status: "idle" | "signing" | "submitted" | "success" | "error"

submit(
  (api) => api.tx.ocex.claimRewards(epoch, amount, proof),
  { successMessage: "Claimed!", waitForFinalization: false }
);
```

Internally: reads `api` from `useNativeApi()`, signer from `useProfile().getSigner()`.

### Key Types

```typescript
type Epoch = {
  id: number;
  status: "Ended" | "Ongoing" | "Upcoming";
  startBlock: number;
  endBlock: number;
  rewardPool: string;   // raw BigInt string (12 decimals)
  endsAt: string;       // ISO timestamp
};

type ClaimableReward = {
  epoch: number;
  pair: string;
  amount: string;         // raw BigInt string
  merkleProof: string[];  // array of 0x-prefixed hex strings
  merkleLeaf: string;     // 0x-prefixed hex
  claimed: boolean;
};

type LeaderboardEntry = {
  rank: number;
  address: string;
  qFinal: string;
  depthScore: string;
  uptimeScore: string;
  makerVolume: string;
  estimatedReward: string;  // raw BigInt string
};

type DMMAssignment = {
  pair: string;
  account: string;
  committedSpread: number;  // basis points
  committedDepth: string;
  committedUptime: number;  // 0–100
  liveUptime: number;       // 0–100
  stipend: string;          // raw BigInt string
};
```

### Amount Formatting Rule

**All amounts are raw BigInt strings with 12 decimal places (`UNIT = 10^12`).**  
Format only at the view layer:

```typescript
function formatPdex(raw: string): string {
  const val = Number(BigInt(raw) / (UNIT / BigInt(10_000))) / 10_000;
  return `${val.toFixed(4)} PDEX`;
}
```

**Never** do arithmetic on formatted strings. Always operate on raw values.

## 9. On-Chain Claim Flow

```
Frontend                    Polkadot Extension         Polkadex Chain
    │                              │                         │
    │  api.tx.ocex.claimRewards()  │                         │
    │──────────────────────────────►                         │
    │                              │  Sign (user approves)   │
    │                              │──────────────────────►  │
    │                              │                         │
    │       tx hash                │                         │
    │◄──────────────────────────────                         │
    │                         (in block)                     │
    │  success event                                         │
    │◄───────────────────────────────────────────────────────│
    │                                                        │
    │  Invalidate queries                                     │
    │  (lmpHistory, lmpRewards)                               │
```

**Extrinsic parameters:**
- `epoch: u32` — epoch number
- `amount: u128` — exact raw PDEX amount (must match Merkle leaf)
- `merkleProof: Vec<H256>` — array of 32-byte hashes

The on-chain pallet verifies the Merkle proof. If wrong proof or wrong amount, extrinsic fails.
